1
El usuario hace click en "Entrar"
templates/login.html — event listener en el form
▼

El browser dispara el evento submit del form. El JS lo intercepta con addEventListener y llama a e.preventDefault() para evitar el comportamiento por defecto (que recargaría la página).

document.getElementById('login-form')selecciona el elemento form del HTML

const formData = new URLSearchParams();URLSearchParams en vez de JSON — el endpoint /login usa OAuth2 que espera application/x-www-form-urlencoded, no JSON
formData.append('username', ...);agrega username al body del request

⚠️ El endpoint /login usa OAuth2PasswordRequestForm de FastAPI, que espera los datos como application/x-www-form-urlencoded (como un form HTML clásico), no como JSON. Por eso se usa URLSearchParams y no JSON.stringify.

5
Verifica la contraseña con argon2
security.py — verify_password()
▼

La librería pwdlib usa el algoritmo argon2 para verificar la password. Argon2 es el algoritmo ganador del Password Hashing Competition (2015) — resistente a ataques de GPU y rainbow tables.

password_hash = PasswordHash.recommended()usa el algoritmo recomendado (argon2id)
def verify_password(plain_pw, hashed_pw):
return password_hash.verify(plain_pw, hashed_pw)hashea "admin" con el mismo salt del hash guardado y compara. Si coincide → True
✅ Nunca se guarda la password en texto plano. El hash incluye un salt único, así que aunque dos usuarios tengan la misma password, sus hashes son diferentes.
6
Genera el JWT y lo devuelve
security.py — create_access_token() → routers/auth.py
▼

Se crea el token con el username, el rol y la fecha de expiración. Se firma con la SECRET_KEY usando HS256.

def create_access_token(data: dict):
to_encode = data.copy()copia el dict para no mutarlo
expire = datetime.now(timezone.utc) + timedelta(minutes=30)expiración: 30 minutos desde ahora (leído de la env var)
to_encode.update({"exp": expire})agrega la expiración al payload
encoded_jwt = jwt.encode(to_encode, SECRET_KEY, algorithm="HS256")firma el token con la SECRET_KEY
return encoded_jwtdevuelve el string "eyJ..."

El token que se genera tiene esta estructura:

{"alg":"HS256","typ":"JWT"} . {"sub":"admin","role":"admin","exp":1749...} . HMAC-SHA256(header+payload, SECRET_KEY)

El router devuelve:

return {"access_token": access_token, "token_type": "bearer"}200 OK — el browser recibe este JSON
7
El browser guarda el token y redirige
login.html — script JS
▼
const data = await response.json();parsea el JSON: {access_token: "eyJ...", token_type: "bearer"}
localStorage.setItem('token', data.access_token);guarda el token en el storage del browser — persiste entre pestañas y recargas
window.location.href = '/home';navega a /home — el browser hace un GET /home nuevo
⚠️ Guardar el JWT en localStorage es funcional pero vulnerable a XSS. En producción, la alternativa más segura son cookies httpOnly (no accesibles por JS). Para este challenge está bien.
8
FastAPI sirve el home.html
main.py — home_page()
▼

El browser hace GET /home. FastAPI matchea la ruta y devuelve el template renderizado por Jinja2. No hay lógica de autenticación acá — la autenticación la maneja el JS del lado del cliente.

@app.get("/home")
def home_page(request: Request):no tiene Depends(get_current_user) — no verifica JWT acá
return templates.TemplateResponse(request=request, name="home.html")sirve el archivo home.html como HTML estático

El home.html carga a su vez el archivo /static/home.css y el script home.js inline.

La verificación de que el usuario está logueado la hace el JS: si no hay token en localStorage, redirige a / inmediatamente. No es tan seguro como un middleware de servidor, pero funciona para este caso.

Cada uno de esos requests llega a FastAPI con el header Authorization: Bearer eyJ.... FastAPI llama a get_current_user que:

  • Extrae el sub (username)

  • Devuelve el objeto User al endpoint
